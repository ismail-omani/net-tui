# net-dis

[English](README.md) | Русский

TUI-инструмент для аудита локальной сети: находит устройства, сканирует сервисы и проверяет,
не остались ли на них заводские (default) учётные данные.

> ⚠️ **Только для своих сетей.** Запускайте инструмент исключительно на сети, которой вы владеете
> или на тестирование которой у вас есть письменное разрешение. Попытки входа на чужие устройства
> могут нарушать закон.

## Возможности

- обнаружение хостов через `arp-scan --localnet` (fallback — `nmap -sn`);
- сканирование портов и сервисов через `nmap -sS/-sT -sV` (+ OS detection при наличии root);
- определение вендора по OUI, продукту nmap и `http-title`;
- подбор дефолтных кредов с приоритетом вендорных пар;
- протоколы: **HTTP/HTTPS** (Basic, Digest, эвристика HTML-форм), **SSH**, **Telnet**, **FTP**,
  **RTSP**, **SNMP v1/v2c**, **VNC**, **MQTT**, **IPP**;
- TUI на Bubble Tea: таблица устройств, живой лог, прогресс, пауза, детали, повторный скан;
- headless-режим и `--dry-run`;
- результаты сразу пишутся на диск, переживают Ctrl+C.

## Требования

- Linux;
- Go 1.26+ для сборки (проверено на 1.27);
- `nmap`;
- `arp-scan` и `sudo` — опционально, но с ними качество обнаружения и определения вендора выше;
- интернет — только для `--fetch-creds` (потом всё работает офлайн).

## Сборка

```bash
go build -o net-dis ./cmd/net-dis
# или
make build
```

## Быстрый старт

```bash
# 1. Скачать списки дефолтных кредов в data/creds/
./net-dis --fetch-creds

# 2. Запустить TUI
./net-dis

# headless, только обнаружение + nmap, без попыток логина
./net-dis --no-tui --yes --dry-run --target 192.168.1.0/24

# headless полный аудит
./net-dis --no-tui --yes --target 192.168.1.0/24
```

При запуске без `--target` инструмент сам смотрит `ip -j a`, отбрасывает loopback и неактивные
интерфейсы. Если активных подсетей несколько — TUI предложит выбор.

`arp-scan` и `nmap -O` требуют root. TUI запрашивает пароль sudo прямо в интерфейсе и держит его
только в памяти. Если sudo недоступен или вы нажали `Esc`, инструмент продолжает работу без
привилегий: `nmap -sn` + `-sT -sV` (без MAC/вендора по OUI и без OS detection). Если в системе
запрещён `sudo` с паролем через stdin (`requiretty`), запустите всё приложение целиком:
`sudo ./net-dis`.

## Управление в TUI

| Клавиша | Действие |
|---|---|
| `↑`/`↓`, `j`/`k` | выбор устройства |
| `Enter` | детали устройства / назад к логу |
| `p` | пауза/продолжить подбор |
| `s` | повторный скан (после завершения) |
| `e` | открыть папку результатов (`xdg-open`) |
| `PgUp`/`PgDn` | прокрутка лога |
| `q`, `Ctrl+C` | выход (уже найденные результаты сохраняются) |

После завершения сканирования TUI показывает итог, сам закрывается примерно через 2 секунды
(клавиша `q` закрывает сразу) и печатает в терминал финальную строку вида
`+ scan done: 3 devices, 0 findings, 42s` и путь к результатам. Так сразу видно, что работа
закончена, а не подвисла.

## Результаты

Для каждого IP, на котором найден хотя бы один рабочий дефолтный логин, создаётся
`results/<ip>.json`:

```json
[
  {
    "protocol": "http",
    "port": 80,
    "vendor": "TP-Link",
    "login": "admin",
    "password": "admin"
  },
  {
    "protocol": "telnet",
    "port": 23,
    "vendor": "TP-Link",
    "login": "admin",
    "password": "admin"
  }
]
```

Дополнительно:

- `results/_devices.json` — инвентарь: MAC, вендор, hostname, все открытые порты/сервисы, находки, заметки;
- `results/_attempts.jsonl` — аудит всех попыток (JSON Lines, **пароли в открытом виде**).

Финальные статусы в `_devices.json`: `found` (есть находки), `clean` (порты проверены, находок нет),
`no ports` (открытых портов не найдено), `scanned` (`--dry-run`).

У `_devices.json` и каждой строки `_attempts.jsonl` есть поле `run` (например,
`20261107-155812`) — это идентификатор запуска. `_attempts.jsonl` дополняется между запусками,
поэтому по `run` легко понять, какие попытки относятся к текущему скану.

Пустые `<ip>.json` не создаются. Запись атомарная (tmp + rename). Повторный скан дополняет
существующие файлы (точные дубликаты не добавляются).

## Как это работает

1. Определение интерфейсов и подсети (`ip -j addr show`).
2. `arp-scan --interface <if> --localnet` → IP, MAC, вендор по OUI.
   Если arp-scan недоступен/пуст — `nmap -sn`.
3. `nmap` по найденным IP: open ports, service/product/version, `http-title`, OS.
4. Вендор уточняется по OUI + продукту nmap + title; нормализуется к каноническому бренду.
   Строки вида `(Unknown: locally administered)` игнорируются, поэтому, например, AmpliFi
   определяется как Ubiquiti по `http-title`, а не остаётся «неизвестным».
5. Для каждого сервиса строится план: вендорные креды (до ~2/3 лимита), затем общий топ
   (`admin/admin`, `root/root`, …), без дублей.
6. Пробы выполняются параллельно: 8 воркеров глобально, не более 2 одновременных попыток на хост,
   пауза 300 мс между попытками, остановка протокола после первого успеха.
7. Находка сразу пишется в `results/<ip>.json` и в аудит-лог.

### Критерии успеха

- **HTTP Basic/Digest** — сервер ответил `401`, после подстановки кредов получен не-`401` ответ;
- **HTTP-форма** — нужны ≥2 сигнала: новая cookie, редирект на другую страницу, исчезла форма
  с паролем, появились слова `dashboard`/`logout`/`welcome`; при этом нет слов
  `invalid`/`incorrect`/`failed` и т.п. При одном сигнале результат считается сомнительным и **не**
  записывается;
- **SSH** — успешная аутентификация `x/crypto/ssh` (password или keyboard-interactive);
- **Telnet** — приглашение `login:`/`password:`, отправка кредов, полученный shell-prompt или
  приветствие, без ошибок входа (с обработкой IAC-негоциации);
- **FTP** — `230` после `USER`/`PASS`;
- **RTSP** — `401` challenge, затем `200` на `DESCRIBE` с Basic/Digest;
- **SNMP** — успешный `GET sysDescr.0` с community `public`/`private` (в `login` пишется пустая
  строка, community — в `password`);
- **VNC** — security type `None` (открытый доступ, пустые login/password) или успешный
  DES challenge-response с дефолтным паролем;
- **MQTT** — `CONNACK` с кодом `0` (анонимно или с кредами);
- **IPP** — `Get-Printer-Attributes` вернул `successful-ok` после Basic-аутентификации.

## База кредов

`--fetch-creds` скачивает в `data/creds/`:

- [SecLists default-passwords.csv](https://github.com/danielmiessler/SecLists) (Vendor, Username, Password);
- [ihebski/DefaultCreds-cheat-sheet](https://github.com/ihebski/DefaultCreds-cheat-sheet);
- [routersploit defaults.txt](https://github.com/threat9/routersploit).

Записи индексируются по бренду (`tp-link`, `hikvision`, `dahua`, `mikrotik`, …), для неизвестных
вендоров используется общий список. Списки можно обновлять вручную — формат парсинга описан в
`internal/creds/store.go`. Без сети инструмент работает с уже скачанными файлами.

## Ограничения

- HTML-формы разбираются эвристически: капчи, JS-шифрование пароля, нестандартные поля и
  двухшаговые логины могут не поддерживаться;
- SNMP-community — это не совсем «логин», но тоже дефолтный секрет;
- VNC `None`, анонимный MQTT и SNMP-community пишутся с пустым `login`;
- сканирование «всех устройств» включает телефоны/ПК — на них тоже будут попытки SSH/Telnet/HTTP;
- активные попытки логина могут заблокировать учётную запись или включить бан IP на камерах/роутерах;
  для чувствительных сетей используйте `--max-creds 1..5` и больший `--timeout`;
- `_attempts.jsonl` содержит все опробованные пароли в открытом виде — храните папку `results/`
  соответствующим образом;
- инструмент не эксплуатирует уязвимости и не обходит аутентификацию: только проверка известных
  заводских пар.
